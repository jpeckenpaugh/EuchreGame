This instructional guide is designed for a coding agent to implement the **Data Factory**, the phase where the "Teacher" model (Gemma 4 9B IT) generates the high-quality synthetic dataset required for the distillation of the student model.

***

# Technical Specification: The Data Factory Pipeline

## 1. Overview
The goal of the Data Factory is to generate a massive library of "Expert Trajectories." A trajectory consists of a specific game state, the reasoning process (internal monologue) used to analyze that state, and the resulting legal move. 

This dataset will be used to train the Student model to not only play Euchre but to **mimic the reasoning process** of the Teacher.

### Hardware Target
- **Host:** AMD Ryzen AI 9 HX 370
- **VRAM Allocation:** 16 GB (iGPU)
- **Teacher Model:** `Gemma-4-9B-IT` (Quantized INT4)
- **Inference Engine:** Ollama (Local API)

---

## 2. Pipeline Architecture
The pipeline is split into three decoupled stages to ensure data quality and allow for prompt iteration without re-simulating games.

### Stage 1: Scenario Generation (`gen_scenarios.py`)
**Objective:** Use the `EuchreGame` engine to generate thousands of unique, randomized game snapshots.
- **Input:** A set of random seeds.
- **Process:** 
    1. Instantiate `EuchreGame`.
    2. Play a game using random legal moves.
    3. At every turn, capture the `get_masked_state()` for the current active player.
- **Output:** `scenarios.jsonl`
    - *Format:* `{"session_id": "...", "turn_id": 0, "masked_state": {...}}`

### Stage 2: Trajectory Generation (`generate_trajectories.py`)
**Objective:** Pass the scenarios through the Teacher model to generate "thoughts" and "actions."
- **Input:** `scenarios.jsonl`.
- **Process:**
    1. Load the `Gemma-4-9B-IT` model via the Ollama API.
    2. For each scenario:
        - Format the `masked_state` into a **Compact State String** (e.g., `T:H | P:1 | L:SK | H:[...] | Leg:[...]`).
        - Construct a prompt requiring a JSON response containing `reasoning` and `move`.
        - Send the request to the local Ollama endpoint.
- **Output:** `raw_responses.jsonl`
    - *Format:* `{"scenario": {...}, "model_response": {...}}`

### Stage 3: Validation & Filtering (`filter_gold_data.py`)
**Objective:** Purge "hallucinations" and illegal moves to ensure the Student model only learns from perfect play.
- **Input:** `raw_responses.jsonl`.
- **Process:**
    1. Parse the `model_response` JSON.
    2. Use the `EuchreGame` engine to verify: **Is the `move` actually in the `legal_moves` list for that state?**
    3. If **Legal**: Save to the final "Gold Dataset."
    4. If **Illegal**: Discard the sample (or log it as a failure for baseline analysis).
- **Output:** `gold_dataset.jsonl` (The final training file).

---

## 3. The "Gold" Dataset Format
The final output must be in a format ready for SFT (Supervised Fine-Tuning). Each line in `gold_dataset.jsonl` must be a single JSON object:

```json
{
  "instruction": "You are a Euchre Expert. State: T:H | P:1 | L:SK | H:[HJ,HQ,DA,S10,C2] | Leg:[S10]",
  "thought": "The lead is the King of Spades. I have no spades, so I cannot follow suit. I hold the Ace of Diamonds, but it is not trump. I will play the 10 of Spades to avoid wasting a high card.",
  "output": "{\"move\": \"S-10\"}"
}
```

---

## 4. Implementation Requirements for the Agent

### A. The Prompt Template
The agent must implement a strict prompt to prevent the model from "chatting."
- **System Prompt:** `You are a professional Euchre expert. You analyze game states and provide a strategic move. You must respond ONLY in JSON. Do not provide introductory or concluding text.`
- **Format:** Use the Gemma Chat Template: `<start_of_turn>user\n{prompt}<end_of_turn>\n<start_of_turn>model\n`

### B. Compact State Serializer
Implement a helper function to convert the `EuchreGame` state into the shorthand format:
- **Trump:** `T:[S/H/D/C]`
- **Player:** `P:[0-3]`
- **Lead:** `L:[Rank][Suit]`
- **Hand:** `H:[Card,Card...]`
- **Legals:** `Leg:[Move,Move...]`

### C. Error Handling & Rate Limiting
- **API Retries:** Implement a retry mechanism for the Ollama API in case of timeouts.
- **Batching:** Process scenarios in batches to optimize GPU throughput.
- **Logging:** Log the percentage of "Legal" vs "Illegal" moves generated by the Teacher to monitor quality.

## 5. Success Criteria
The Data Factory is complete when:
1.  `scenarios.jsonl` contains $\ge 100,000$ unique game states.
2.  `gold_dataset.jsonl` contains $\ge 50,000$ validated, legal "Thought $\rightarrow$ Move" pairs.
3.  The dataset is successfully verified as a valid JSONL file, ready for the training pipeline.
